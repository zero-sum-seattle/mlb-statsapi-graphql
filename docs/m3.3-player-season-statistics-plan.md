# Proposed M3.3: basic player season split statistics

Status: follow-up implementation outline for review; not started or committed
for delivery. Depends on acceptance of the
[M3.2 architecture](m3.2-statistics-architecture.md) in
[issue #10](https://github.com/zero-sum-seattle/mlb-statsapi-graphql/issues/10).

## Deliverable and scope

Implement only `Player.seasonHitting(season:)` and
`Player.seasonPitching(season:)` with the exact curated types and semantics
proposed in M3.2. Return regular-season MLB split rows with provenance; offer
no authoritative-total shortcut. Preserve all existing fields and M3.1
team-season behavior.

1. Add explicit Strawberry envelope, split, provenance, and scope DTOs. Keep
   Pydantic models out of public type annotations and values. Preserve existing
   IDs as integers and names as currently exposed.
2. Add a small player-season mapper, separate from `team_stats.season_total`.
   Validate block/model identity, filter incompatible echoed scope metadata,
   preserve parsed indices/order/duplicates, map only curated fields, enforce
   finite numeric and innings consistency rules, and retain missing versus
   zero semantics. Do not create a generic stats framework.
3. Add one request-scoped loader using the exact combined-group key and
   `get_player_stats` arguments in M3.2. Use `_fetch_each` and the shared
   `RequestLookups.run("player_season_stats", ...)` path. Keep failed futures
   cached per request. No library upgrade or transport change.
4. Add lazy nested resolvers, validate seasons before loader calls, declare
   weight 5 with the shared cache identity, and keep error masking consistent.
   No per-split I/O, dynamic filters, list cardinality declaration, or roster
   cost workaround.
5. Extend the README with executable examples, field meanings, numeric display
   conventions, missing-group behavior, the overlapping-splits warning, shared
   lookup behavior, and the roster-descendant cost restriction. Replace the
   proposed SDL reference with links to implemented behavior only after tests.

## Concrete acceptance tests

Use offline HTTPX MockTransport replay through the locked library for parsing
contracts, and AsyncMock client methods for GraphQL/loader behavior. The
[M3.2 captures](research/m3.2/fixtures/) are regression inputs; copy or reuse
them deliberately without live network in CI. Keep synthetic responses clearly
identified. Promote relevant research assertions into maintained tests rather
than treating the research probe as a production compatibility suite.

| Area | Required cases and observable assertions |
| --- | --- |
| Public contract | Schema snapshot adds only the proposed player fields/types; existing M3.1 SDL and responses unchanged; no JSON or Pydantic-derived public types; every custom resolver passes the declaration guard |
| Single-team season | Soto 2024 produces one TEAM row, correct IDs/year/game type and null `numTeams`; no extra person/team fetches for provenance |
| Trade overlap | Soto 2022 preserves all three rows: multi-team 27 HR, Washington 21, San Diego 6; never emits 54 as a total; reversing input order does not change row values/scope or select a different total |
| Pitching and leagues | Scherzer 2023 preserves teams 121/140, null aggregate league, `numTeams=2`, `numLeagues=2`; `152.2` remains a string and matches 458 outs |
| Two-way player | Ohtani 2023 returns independent hitting/pitching DTOs from one combined lookup; Ohtani 2024 pitching is null without invented zero values or an error |
| Ambiguity | Two no-team rows with missing aggregate markers, duplicate team IDs, conflicting team/numTeams, partial metadata, and duplicate identical rows remain separate; UNSPECIFIED is used as defined; no sum, first-row choice, or inferred complete season |
| Scope filtering | Wrong supplied player, season, game type, or sport and position-specific rows are excluded; absent optional metadata remains null in provenance; indices refer to original parsed positions, including gaps; all rejected rows yield null |
| Missing values | Empty response/block/splits and 404 yield null; missing leaf, explicit null, and known rate sentinels map to null; real zeros remain zero; unknown-only parsed payload retains an all-null row with provenance |
| Numeric mapping | `.287` becomes `0.287`; `1.000` has no exact display-precision promise; OPS may exceed 1; NaN/infinity, negative counts, nonpositive IDs, out-of-range integers, malformed innings `6.3`, and outs/innings disagreement produce safe upstream errors; absent outs is not derived |
| Validation and laziness | Season 999/10000 rejected before stats I/O; 1000/9999 forwarded without coverage guarantee; identity-only, skipped, and missing-player selections do not load stats; invalid season does not block a valid sibling season |
| Cache and arguments | Both groups, fragments, default variables, repeated roots, and aliases share exactly one combined call per key; exact arguments include both groups, season, `R`, sport 1; different seasons/players use separate calls; new HTTP request has fresh caches |
| Cost | Root player plus both groups costs 10; a second season costs 15; two distinct players with stats cost 20; skipped fields cost nothing; over-budget operation performs zero lookups; roster→player→season stats is infinite and rejected; split scalar/provenance selection stays free |
| Error isolation | Known HTTP 400/429/5xx, transport/timeout/decode, and validation errors are client-safe and cached once per key; another key succeeds; next request retries; alias error paths remain separate; unexpected failures stay masked; shared response parser failure may affect both groups |
| Mapper failure isolation | A successful combined load with valid hitting but an invalid mapped pitching value leaves hitting available, nulls pitching with an upstream error; mismatched block or row model is an error, not absence |
| Admission and lifecycle | Player stats compete with team/person/roster/M3.1 on the same worker semaphore across overlapping requests; cache hits do not increment lookup count; success/failure/cancellation release permits; queued cancellation never calls the client; cleanup awaits tasks and records the new lookup kind |

Keep upstream parser limitations visible: unsupported response groups can fail
before mapping, empty raw rows can disappear, and repeated group/type blocks can
overwrite earlier data. Do not claim these are repaired by the public mapper.
No test should require production to reconstruct metadata the library discarded.

## Proposed query example

This becomes runnable only in M3.3:

```graphql
query PlayerSeason($id: Int!, $season: Int!) {
  player(id: $id) {
    id
    fullName
    seasonHitting(season: $season) {
      playerId
      season
      gameType
      splits {
        provenance { parsedIndex scope teamId numTeams leagueId }
        homeRuns
        battingAverage
      }
    }
    seasonPitching(season: $season) {
      splits {
        provenance { parsedIndex scope teamId numTeams }
        inningsPitched
        outs
        earnedRunAverage
      }
    }
  }
}
```

For Soto 2022, hitting home-run values are `[27, 21, 6]` with scopes
`[MULTI_TEAM, TEAM, TEAM]`, and team IDs `[null, 120, 135]` in captured order.
These are overlapping rows, not numbers to add. Order may change upstream.

## Exit checks and exclusions

Run the entire offline test suite under `uv run --locked pytest`, build with
`uv build`, check `git diff --check`, and review the public SDL delta. Verify
the README examples against the implementation and its configured cost/depth
limits. No live API access is required in CI. Ship in a separate PR after M3.2
review; do not mark implementation complete from this design branch.

Exclude advanced stats, career/year-by-year queries, game/play/pitch logs,
leaderboards/rankings, date ranges, arbitrary group/type JSON passthrough,
team-filter arguments, authoritative or calculated player totals, new team
statistics, roster bounding/truncation, true HTTP batching, cross-request caches,
new clients/retries, dependency upgrades, and operational hardening. Each would
need its own narrowly scoped evidence and contract.
